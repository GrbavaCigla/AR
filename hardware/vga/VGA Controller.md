# VGA Controller

Verilog module for generating VGA video signals (`HS`, `VS`, `DISPLAY`) and current pixel coordinates (`X`, `Y`) based on an input pixel clock. Designed in the Quartus II Block/Schematic Editor (`Controller.bdf`), with an automatically generated Verilog file (`Controller.v`).

## Current status

The controller is configured for standard **640×480 @ 60Hz** VGA timing:

- Horizontal: 640 visible pixels, total 800 (16 front porch + 96 sync + 48 back porch)
- Vertical: 480 visible lines, total 525 (10 front porch + 2 sync + 33 back porch)

## Architecture

The controller is built from a few reusable building blocks (each defined as a separate component module):

- **`RegisterX`** – a counter with `CLK`, `CL` (clear), and `INC` (increment) inputs; used for the `X` and `Y` pixel counters.
- **`ConstantX`** – outputs a fixed constant of a given width (`size`) and value (`const`); used for all timing boundary values (front porch, sync, back porch, resolution).
- **`ComparatorX`** – compares two `size`-bit inputs `A` and `B`, with outputs `LS` (A<B), `EQ` (A=B), `GR` (A>B).

### Counting logic

- **X counter** (11 bits) counts from 0 to 799. When `X` reaches 799 (`EQ`), the counter resets to 0 (`CL`) and the `Y` counter is incremented by 1 (`INC`).
- **Y counter** (10 bits) counts from 0 to 524, synchronized with the end of each row. When `Y` reaches 524 (with `X` also at 799), both counters reset — a new frame begins.

### Signal generation

- **`DISPLAY`** = `(X < 640) AND (Y < 480)` — active only within the visible image area.
- **`HS`** = `(X > 655) AND (X < 752)` — horizontal sync pulse, active for `X` in [656, 751] (96 cycles), matching the standard front porch/sync/back porch split.
- **`VS`** = `(Y > 489) AND (Y < 492)` — vertical sync pulse, active for `Y` in [490, 491] (2 lines), matching the standard front porch/sync/back porch split.

All boundary parameters (image dimensions, sync pulse positions and widths) are hardcoded as `defparam const = ...` values on the `ConstantX` instances, meaning any further change to resolution/timing is done purely by editing those constants.

## Important note on the pixel clock

The pixel clock (`CLK`) is fed directly into the module, with no internal PLL/clock-divider logic — the clock source is defined at a higher level of the project (e.g. a PLL megafunction) and is **not part of this module**.

Standard VGA 640×480 @ 60Hz requires a pixel clock of **25.175 MHz** (commonly approximated as 25 MHz in practice). If the upstream PLL/clock source still supplies the frequency used for the previous resolution, `CLK` **must** be reconfigured to ~25 MHz — otherwise the horizontal/vertical timing generated by this controller will be correct in pixel counts, but the actual refresh rate and signal timing seen by the monitor will be wrong, likely resulting in no picture or an unstable/out-of-range display.

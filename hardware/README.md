# Hardware

Everything that runs on the FPGA. The design is drawn in Quartus **Block Diagram
Files** (`.bdf`); the `.v` files beside them are generated output. Edit the
`.bdf`, never the `.v`.

Open `riscv32i processor/Riscv32i.qsf` in Quartus 13.1. Top-level entity is
**`MainScheme`** (in `riscv32i processor/mainScheme/`), which wires together the
CPU, bus decoder, SDRAM, VGA and LiDAR.

## Folders

| Folder | What's in it |
|---|---|
| [`riscv32i processor/`](riscv32i%20processor/) | The CPU itself and the top-level `MainScheme` that instantiates everything |
| [`lidar/`](lidar/) | UART receiver, LD14P packet parser, polar→pixel maths, point FIFO |
| [`vga/`](vga/) | Framebuffer, double buffering, sync generation, scanout |
| [`bus/`](bus/) | Address decoding, wait-state FSM, VGA bus interface |
| [`sdram/`](sdram/) | SDRAM controller, arbiter and CPU-facing wrapper |
| [`components/`](components/) | Reusable building blocks — adders, muxes, registers, comparators |
| [`tests/`](tests/) | Standalone Quartus projects for bringing up each block on its own |

## How a point reaches the screen

```
LD14P ──UART──> UART_RX ──bytes──> PacketParser ──12 points──> AngleGenerator
                                                                     │
                                                              CalculateXY2
                                                          (polar → x,y pixel)
                                                                     │
                                                                 LidarFifo
                                                                     │
                                        CPU reads 0x1000_0000, one point per read
                                                                     │
                                       CPU writes pixel to 0x2000_0000 (VGA)
                                                                     │
                                              FrameBuffer ──> Monitor ──> VGA
```

## Build artifacts

`db/`, `incremental_db/`, `greybox_tmp/`, `hc_output/` and `output_files/` are
generated by Quartus on every compile. They are not source and can be deleted
freely — Quartus recreates them.
